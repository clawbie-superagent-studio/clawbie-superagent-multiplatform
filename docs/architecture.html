📡 输入源 (Input Sources)
所有触发 Clawbie 工作的入口 — 消息从这里进入系统
💬 客户端聊天框 Tauri 桌面 App / Web UI / CLI
用户直接和 Clawbie 对话的主界面 📱 三方社交软件 微信 / Telegram / Discord / Slack 等
通过 Bridge 转发消息到 Clawbie 🦞 Clawbie 自有 App Clawbie 独立开发的移动端/桌面端应用
深度集成，原生体验 📡 感知设备 摄像头 / IoT 传感器 / 无人机 / AR 眼镜等
设备主动上报事件（如检测到异常）
或定时采集数据推送给 Clawbie ⏰ 内部定时机制 cron 定时任务 / 轮询检查 / 事件触发
包括设备的定时采集任务
无需用户干预，Clawbie 自主执行

Layer 2 — 分流层
🔀 分流器 (Router)
纯代码逻辑，零 token 消耗，毫秒级响应 — 决定"谁来处理这条消息"
消息队列 (按优先级排序)
P0 用户直接对话 最高优先级，要求即时响应感
来自客户端聊天框 / 自有 App P1 Worker 求助 员工卡住了，需要 Clawbie 决策
status = stuck，有 blocker.md P2 Worker 完成通知 员工完成任务，汇报结果
status = done，有 result.md P3 社交软件消息 来自 Telegram / 微信等 Bridge
优先级低于本地交互 P4 定时任务触发 cron 到点 / 轮询有结果
最低优先级，可排队等待
分流规则 (Rust 代码层)
Clawbie 空闲？
→ 直接交给 Clawbie 处理
Clawbie 忙 + 消息紧急？
→ 生成临时分身处理
Clawbie 忙 + 消息不急？
→ 入队等待，按优先级排
已标记为定时/后台任务？
→ 直接派给 Worker，不经 Clawbie
